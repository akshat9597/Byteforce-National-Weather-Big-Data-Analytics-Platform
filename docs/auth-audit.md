# Authentication integration audit

Audited before this change: Next.js 15 / React 19 / TypeScript frontend, FastAPI/Python backend, SQLAlchemy ORM, SQLite locally and PostgreSQL/PostGIS in Docker. Existing user model has email, password hash, role, profile and organization. Existing roles: Administrator, Weather Analyst, Verification Officer, Viewer. The login component offers OTP and password; no public signup existed. Authentication uses backend-issued eight-hour JWT HttpOnly cookies, backend current-user/role dependencies and origin checks. The frontend displays login when unauthenticated. Existing OTP challenges, database rate limits and a custom HTTP Resend adapter were already present.

Integration decision: retain all existing users, roles, password login and session code. Use official Python Resend SDK on the backend. Extend existing challenges with email and lifecycle timestamps; add last login to existing users. Reuse Viewer as the least privileged existing role for verified signup. Add true page redirects while retaining backend route guards. Preserve old OTP routes only as deprecated compatibility aliases. No frontend credential storage, no separate user database, no schema replacement. Source references under sources/ remain untouched.

Configuration audit found an existing backend Resend key; its value was not printed or copied into documentation/client code. EMAIL_FROM is now authoritative, with the old RESEND_FROM recognized as a compatibility fallback. External delivery testing is restricted to the recipient explicitly supplied by the user.
